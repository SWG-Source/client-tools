# Original PCRE and libxml2 providers for x64

The x64 client builds PCRE 4.1 and libxml2 2.6.7 from verified source with native VS2013. Win32 retains its existing providers. No generated binaries are committed. Supply offline archives through `SwgPcreArchive` and `SwgLibxmlArchive`; the builder refuses other hashes and does not download.

| Source | SHA256 |
|---|---|
| [PCRE 4.1](https://downloads.sourceforge.net/project/pcre/pcre/4.1/pcre-4.1.tar.gz) | `9ac01a6c5763120732c560ac26890c79c6ec0f8df4f5d42c2a6f0cae50c25575` |
| [libxml2 2.6.7](https://download.gnome.org/sources/libxml2/2.6/libxml2-2.6.7.tar.gz) | `785dec9ef48babf65f06c2dd98d6ef2ab2da09259af8f41c913c014046d5a39b` |

The XML digest matches GNOME's published checksum. The PCRE digest records the retrieved official project archive; no independently signed digest was established. Licenses are retained alongside built outputs.

PCRE uses the original public header, static ABI, UTF-8 enabled, newline10 and link-size2. Those feature settings were queried from the original Win32 archive. Tables are generated by the original tool in the C startup locale. The POSIX allocation threshold10 is the upstream default. Release uses `/MT`, Debug `/MTd`.

XML stays a DLL, preserving the imported `xmlFree` variable and allocator-hook ABI. Feature options follow the repository's original `libxml-configure-win32.bat`; Release and Debug retain their different XML/memory debugging settings. The repository's separate libxml2.4.28 source is not used. The sole upstream makefile adaptation removes `/OPT:NOWIN98`, which v120 rejects. No parser feature is removed or substituted.

`parser-deps.props` replaces only the named old x86 PCRE/XML inputs. Outputs live under `compile/deps/parsers-v120/x64/<Configuration>/`; override `SwgParserDepsDir` only with a private directory belonging to this checkout/configuration. Every invocation rebuilds, with a bounded directory lock and ownership check; there is no external-toolchain cache claim. Failed builds stop the link. Do not run concurrent consumers against one directory from different source revisions.

After a successful link, the matching generated `libxml2.dll` is copied to `$(TargetDir)`. Distributing or testing the executable requires that DLL next to it. The existing Win32 DLL is unchanged. Runtime-path validation is separate from successful import-library linking.

Bounded validation established native source builds and allocator/regex/XML smoke checks on both ABIs/configurations, plus the upstream PCRE testinput1 reference output (line endings normalized only). These checks do not establish all UTF-8/XML behavior, full gameplay or compatibility of unrelated vendor providers. Keep native full-client link/run evidence separate.
